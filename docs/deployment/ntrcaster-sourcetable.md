# NTRIP sourcetable delivery — rek-d01 → ntrcaster.vedur.is

The caster's `/etc/ntripcaster/sourcetable.dat` is generated by
`tosGPS sourcetable` (tostools), reviewed, committed to
`gps-config-data/ntrcaster/sourcetable.dat`, and delivered by rek-d01. The
caster cannot pull it itself: ntrcaster (gpscoll02, Debian 8) has no git and no
python, and it has no route to git.vedur.is.

```
gps-config-data ──gps-config-sync (bgo, 10 min)──► rek-d01 clone
   rek-d01 gpsops: gps-ntrcaster-sourcetable.timer (10 min, convergent)
      ssh (forced-command key) ──► ntrcaster: ~gpsops/bin/ntrcaster-sourcetable
         status | install: validate → backup → write in place → admin?mode=rehash
```

| Piece | Where it lives | Runs on |
|---|---|---|
| `deployment/server/push-ntrcaster-sourcetable.sh` | this repo | rek-d01, gpsops |
| `deployment/systemd/gps-ntrcaster-sourcetable.{service,timer}` | this repo | rek-d01, gpsops `--user` |
| `deployment/ntrcaster/ntrcaster-sourcetable` | this repo, copied by hand | ntrcaster, gpsops |

## Caster behaviour (checked in the 2.0.45 source, not assumed)

- `sourcetable.dat` is read **at startup and on `rehash` only**
  (`main.c`, `commands.c:com_rehash`). **SIGHUP does not re-read it**: it
  re-reads `ntripcaster.conf` and the log files only (`main.c:sig_hup`).
- `rehash` (`/admin?mode=rehash`, or the telnet `rehash` command) re-parses
  `ntripcaster.conf`, the `*.aut` files and the sourcetable, and keeps
  streams connected (manual §11). It applies **any** pending edit in those
  files, not only the sourcetable.
- The merge is keyed by mountpoint (`sourcetable.c:read_sourcetable`, `avl_replace`):
  - a **changed** line takes effect immediately;
  - a **new** line for a source that is **already connected** stays hidden.
    The show flag is set only when a source connects (`sourcetable_add_source`),
    and the function that would refresh it, `sourcetable_set_show_status`, has
    no callers. The line appears when the source next reconnects, or after a
    restart;
  - a line **removed** from the file stays loaded until a restart.
- STR lines whose mount is not fed are never served (`send_sourcetable` only
  sends `show == 1`). On 2026-11-03 the file had 64 STR lines and the caster
  served 45; the 19 hidden ones were exactly the not-fed mounts. Leaving a line
  for a dead stream in the file is therefore harmless.

So routine updates need **no restart**. The first deployment adds about 110
lines for streams that are already connected, and those stay hidden until each
source reconnects. Do **one restart** after that first install (kill the PID
on :2101; casterwatch brings it back in about 4 s; see the `ntrcaster` memory).
RTK pairs on rtk.vedur.is that lose their stream may need
`~/bin/restart-rtk.sh pair NN`.

## One-time setup

All steps are done by hand. Steps 2 and 3 need write access to gpsops's files
on ntrcaster.

1. **Key on rek-d01** (as gpsops):
   ```bash
   ssh-keygen -t ed25519 -N '' -C rek-d01-sourcetable -f ~/.ssh/ntrcaster_sourcetable
   cat ~/.ssh/ntrcaster_sourcetable.pub
   ```
2. **Forced command on ntrcaster** (as gpsops): install the script and
   restrict the key to it. rek-d01's address is 10.170.80.15.
   ```bash
   mkdir -p ~/bin && install -m 755 ntrcaster-sourcetable ~/bin/   # copied from this repo
   echo 'command="/home/gpsops/bin/ntrcaster-sourcetable",from="10.170.80.15",no-pty,no-port-forwarding,no-agent-forwarding,no-X11-forwarding <PUBKEY>' >> ~/.ssh/authorized_keys
   ```
3. **Rehash credential on ntrcaster**: an account in the caster's admin group,
   one line `user:password`. A password must not contain `"` or `\`, because it
   is passed to curl as a `-K` config line. Without this file the script still
   installs, but logs "NOT rehashed".
   ```bash
   mkdir -p ~/.config/ntrcaster && (umask 077; editor ~/.config/ntrcaster/admin.cred)
   ```
4. **Smoke test from rek-d01**, then enable the timer:
   ```bash
   ssh -i ~/.ssh/ntrcaster_sourcetable gpsops@ntrcaster.vedur.is status   # sha256 … str N
   ssh -i ~/.ssh/ntrcaster_sourcetable gpsops@ntrcaster.vedur.is 'ls /'   # must print the usage line
   cp ~bgo/git/receivers/deployment/systemd/gps-ntrcaster-sourcetable.{service,timer} ~/.config/systemd/user/
   systemctl --user daemon-reload && systemctl --user enable --now gps-ntrcaster-sourcetable.timer
   ```
5. **First delivery**: run the service once by hand and watch it, then restart
   the caster once (see above):
   ```bash
   systemctl --user start gps-ntrcaster-sourcetable && journalctl --user-unit gps-ntrcaster-sourcetable -n 5
   ```

## What `install` refuses

Each refusal is logged to `~gpsops/sourcetable/install.log` on ntrcaster, and
the live file is left alone.

- empty input, or larger than 256 KiB;
- CR line endings, or any byte outside printable ASCII. The 2021 file had
  Latin-1 names; the generator writes ASCII;
- a first line that is not `CAS;`, a missing `NET;` record, or an unknown
  record type;
- an STR line with fewer than 18 or more than 19 fields, or a bad mountpoint
  name, or a duplicate mountpoint;
- **an STR count more than 20 % below the live file's.** The generator never
  drops lines, so a large shrink means a truncated or wrong file. Removing
  mounts is a deliberate hand step.

An identical file prints `unchanged` and does nothing, so the timer is a no-op
on a converged system.

## Rollback

On ntrcaster, as gpsops: the newest backup is the file as it was before the
last install (30 are kept).
```bash
ls -1t ~/sourcetable/backup/ | head -3
cat ~/sourcetable/backup/sourcetable.dat.<STAMP> > /etc/ntripcaster/sourcetable.dat
# then rehash (admin?mode=rehash). ALSO revert the gps-config-data commit,
# or the timer re-delivers the bad version within 10 minutes.
```
To pause delivery: `systemctl --user stop gps-ntrcaster-sourcetable.timer` on rek-d01.
